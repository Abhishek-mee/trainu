# Design notes

Trainu has two interfaces with different jobs. The phone is a viewing room; the laptop is a projection booth. They share a brand mark, but not a visual language.

These notes are the reference for future UI work. If a change conflicts with them, change the notes first and explain why.

## Brand

- Name: **Trainu**
- Mark: a red play triangle, used alone or before the wordmark.
- Voice: calm, precise, a little cinematic. Short sentences. No hype, no fake metrics, no "revolutionary".
- Tagline: **Your laptop, on your phone.**
- Never use Netflix logos, wordmarks, screenshots or assets. The phone may feel Netflix-adjacent; it must not pretend to be Netflix.

## Phone: the viewing room

The phone is inspired by the clarity of a streaming service: pure black, one strong red, big cinematic art, and a player that gets out of the way. It is not a copy of any streaming brand.

### Palette

| Token | Value | Use |
| --- | --- | --- |
| `--bg` | `#000000` | Page background |
| `--surface` | `#141414` | Cards and raised panels |
| `--surface-2` | `#1f1f1f` | Secondary surfaces |
| `--surface-3` | `#2b2b2b` | Hover and pressed states |
| `--nf-red` | `#e50914` | Primary action, progress, active tab |
| `--nf-red-hover` | `#f6121d` | Hover |
| `--nf-red-deep` | `#b20710` | Deep accent |
| `--text` | `#ffffff` | Primary text |
| `--muted` | `#b3b3b3` | Secondary text |
| `--muted-2` | `#8c8c8c` | Metadata |
| `--muted-3` | `#6b6b6b` | Faint labels |
| `--ok` | `#46d369` | Connected status only |

Poster fallbacks use neutral black and grey gradients. Do not introduce warm brown/orange fallbacks; the art should feel cool and cinematic even when a thumbnail is missing.

### Type

- Family: `"Helvetica Neue", Roboto, "Segoe UI", Arial, sans-serif`.
- Display: heavy weights, tight tracking, large sizes. The billboard title is the loudest thing on the screen.
- Body: regular weight, generous line height.
- Labels: uppercase, letter-spaced, small; use sparingly.

### Layout

- Single column, 16px gutters, edge-to-edge billboard.
- Billboard: backdrop image, dark gradient, eyebrow, title, metadata, red **Play** and grey **Browse**.
- Library: two-column poster grid on phones, with title, size and progress beneath.
- Bottom tab bar: Library, Continue, Folders, Settings. It is fixed and must respect safe-area insets.
- Player: full-screen black, red seek bar, white controls, 10-second skip, speed, PiP, fullscreen, subtitles. Controls auto-hide during playback.
- Pair page: a paper ticket / cinema pass metaphor, with a barcode and "Admit one".

### Motion

- Short, eased transitions (150–250ms) for surfaces and controls.
- The hero may cross-fade, but never move under the user's thumb.
- Respect `prefers-reduced-motion`: remove pulses and non-essential movement.

### Accessibility

- Minimum 44×44px touch targets for primary controls.
- Visible focus rings on all interactive elements.
- Labels for icon-only buttons.
- Do not rely on color alone for status; include text.
- Keep contrast at or above WCAG AA for body text.
- The player must remain usable with keyboard and screen readers.

## Laptop panel: the projection booth

The panel is a control surface, not a poster wall. It is inspired by monochrome editorial tools: black, white, cool grey, thin rules, mono labels, and one generated isometric figure. The phone's red belongs to the phone.

### Palette

| Token | Value | Use |
| --- | --- | --- |
| `--bg` | `#000000` | Page background |
| `--surface` | `#0a0a0b` | Panels |
| `--surface-2` | `#111113` | Inset surfaces |
| `--surface-3` | `#18181b` | Hover |
| `--line` | `#27272a` | Borders |
| `--line-strong` | `#3a3a3e` | Strong borders |
| `--text` | `#ffffff` | Primary text |
| `--muted` | `#a1a5ad` | Body text |
| `--muted-2` | `#767d88` | Secondary text |
| `--muted-3` | `#5b606a` | Labels |
| `--ok` | `#9fce9a` | Ready / connected |
| `--danger` | `#ff8f7a` | Errors |

### Type and layout

- Family: `"Inter", "Segoe UI Variable Text", "Segoe UI", system-ui, ...`.
- Labels: mono, uppercase, 10–11px, wide tracking.
- Layout: hero with copy and the isometric screening desk; then a two-column grid of Link, Library, Engine and Activity panels.
- Panels use thin borders, 4–8px radii and almost no shadow. Density is intentional.
- The hero figure is generated by `scripts/make-signal-figure.mjs` into `public/iso-local-link.svg`. Edit the script and regenerate; do not hand-edit the SVG.

### USB flow

The USB debugging tab must make one path obvious:

1. Unlock the phone, choose **File transfer**, enable **USB debugging**.
2. Press **Connect phone**.
3. Trainu restarts adb when authorization is stale and waits up to 20 seconds for the Android RSA prompt.
4. When the phone is authorized, Trainu runs `adb reverse` and selects the localhost QR.
5. If the prompt never appears, **Phone prompt not showing?** opens the File transfer, revoke, cable/port and Xiaomi/HyperOS steps.

The waiting state is a live region (`aria-live="polite"`). The button is disabled while waiting and the result is announced as text, not only as a color.

## Pair page

- A ticket that reads like a cinema pass: ribbon, tear line, barcode, "Admit one".
- The panel URL is always `127.0.0.1:<adminPort>/desktop`, never the main phone port.
- The page is public only to explain pairing. It must not reveal the token, a library path, or the admin panel itself.

## Responsive checks

- Phone: 393×851, 360×800, 320×800. No horizontal overflow.
- Pair page: 393×851.
- Panel: 1120, 860, 660 px. The grid may collapse, but the figure, QR and method panel must remain usable.

## Public screenshots

Public screenshots use the synthetic demo library in `docs/screenshots/`. They must never show a real folder name, a personal filename, a token, a LAN address that identifies a home network, or the user's admin URL. The demo panel uses a clean data path and a demo library path on purpose.

## What not to do

- Do not apply the phone's red to the laptop panel.
- Do not add a third theme, a gradient-heavy "AI" look, glassmorphism, or decorative blobs.
- Do not use external fonts, icon packs, images or CDNs.
- Do not add autoplay audio, fake notifications, fake counts or engagement bait.
- Do not hide the pairing code or the privacy guarantees behind a menu.
